A **service** is a piece of code that other code uses: a database connection, a mailer, a
class that finds users. You write it once, and Suku hands it to every route or service that
asks for it. You never write `new UsersService(...)` yourself.

The part of Suku that creates services and hands them out is called the **container**.

## Write a service

There are two ways. Both do the same job, so pick the one you like.

<Tabs items={['With a class', 'Without a class']}>
  <Tab value="With a class">
    List what the service needs in the constructor. Suku passes it in.

    ```ts
    import { Service } from '@sukujs/core';

    @Service()
    export class UsersService {
      constructor(private readonly db: Database) {}

      find(id: number) {
        return this.db.users.get(id);
      }
    }
    ```
  </Tab>
  <Tab value="Without a class">
    List what the service needs in `services`, and return the service from `create`. Its type
    is worked out for you.

    ```ts
    import { service } from '@sukujs/core';

    export const UsersService = service('users', {
      services: { db: Database },
      create: ({ db }) => ({
        find: (id: number) => db.users.get(id),
      }),
    });
    ```
  </Tab>
</Tabs>

## Register it

A service must be registered before anything can use it. Add it to the `services` of a
feature, or of `Suku.create`.

```ts
feature('users', { services: [UsersService] });
```

Both kinds of service register the same way, and each can depend on the other.

## Use it

In a route, name the services you need. They arrive in the handler.

```ts
route.get('/users/:id', {
  services: { users: UsersService },
  handle: ({ users, params }) => users.find(Number(params.id)),
});
```

In a class, ask for it in the constructor, as `UsersService` asks for `Database` above.

## When `@Service()` is needed

`@Service()` does nothing by itself. It only makes TypeScript write down the types of the
constructor's parameters, which is how Suku knows what to pass in.

| Your class | Needs `@Service()`? |
| --- | --- |
| Has no constructor parameters | No |
| Has constructor parameters | Yes, or a `static inject` array |
| Already has `@Routes()` | No |
| Should have a default lifetime | `@Service({ lifetime: 'scoped' })`, or register with `scoped(...)` |

If you forget it on a class that needs it, the app stops at startup with a message that names
the class.

## Lifetimes

A **lifetime** says how long one copy of a service lives, and who shares it. There are three.

| Lifetime | How many are created | Use it for |
| --- | --- | --- |
| `singleton` | One for the whole app. Every request gets the same one. | Configuration, database connections, services that keep no per-request data. |
| `scoped` | One for each request. A new request gets a new one. | The current user, a transaction, anything that belongs to one request. |
| `transient` | A new one every time something asks for it. | Small helpers that should never be shared. |

`singleton` is the default. When you are unsure, use it.

A lifetime given with `singleton(...)`, `scoped(...)` or `transient(...)` always wins over the
one written in `@Service({ lifetime })`.

Choose the lifetime when you register the service.

```ts
import { scoped, singleton, transient } from '@sukujs/core';

services: [singleton(Database), scoped(Cart), transient(Ticket)];
```

A service is created the first time something needs it, not when the app starts.

<Callout title="What is a scope?">
  A scope is a box that holds the services made for one piece of work. Suku opens a scope for
  every request and closes it when the request ends. A scoped service lives in that box. This
  is why you cannot ask for a scoped service outside a request: there is no box to put it in,
  and Suku throws an error.
</Callout>

`examples/lifecycle` in the repository is a small app that prints a line each time a service
is created or cleaned up. Run it to see the three lifetimes side by side.

## Cleaning up (disposal) [#disposal]

Some services hold something that must be closed: a database connection, a file, a timer.
Give the service a `dispose()` method and Suku calls it when the service is no longer needed.
This is called **disposing** the service. You never call `dispose()` yourself.

```ts
@Service()
class UnitOfWork {
  async dispose() {
    await this.connection.release();
  }
}
```

When it is called depends on the lifetime.

| Lifetime | Disposed when |
| --- | --- |
| `singleton` | The app closes (`app.close()`). |
| `scoped` | The request ends. |
| `transient` | The request that asked for it ends. If a singleton asked for it, when the app closes. |

Good to know:

- **`dispose()` is optional.** A service without it is simply dropped.
- **It can be `async`.** Suku waits for it to finish.
- **The newest service is disposed first.** A service is therefore always cleaned up before
  the services it depends on.
- **There is no "on start" method.** Do setup work in the constructor, or in `create`.
- **`value()` registrations are never disposed.** You made the object, so you clean it up.

<Callout title="Other names for dispose()">
  Suku also accepts `onDispose()`, `[Symbol.dispose]()` and `[Symbol.asyncDispose]()`. If a
  service has more than one of these, only one is called. The order of preference is
  `[Symbol.asyncDispose]`, `[Symbol.dispose]`, `dispose`, `onDispose`.
</Callout>

## Services without a class

`service(name, options)` returns one value that you use everywhere: to register the service
and to ask for it.

```ts
export const Clock = service('clock', () => ({ now: () => new Date() }));

export const Invoices = service('invoices', {
  lifetime: 'scoped',
  services: { clock: Clock, db: Database },
  create: ({ clock, db }) => ({
    due: () => db.invoices.dueBefore(clock.now()),
  }),
});
```

Ask for it by name in a route, or in another service.

```ts
route.get('/invoices/due', {
  services: { invoices: Invoices },
  handle: ({ invoices }) => invoices.due(),      // fully typed
});
```

In a class constructor, use `@Inject` to ask for it and `ServiceOf` to get its type.

```ts
@Service()
class Reports {
  constructor(@Inject(Invoices) private readonly invoices: ServiceOf<typeof Invoices>) {}
}
```

Everything else works as it does for a class. The services it needs are checked at startup,
and if the object you return has a `dispose()` method, it is disposed like any other service.

## Tokens

A **token** is the name you use to ask for a service. A class is its own token, so most of the
time you do not think about tokens at all.

You need one in two cases.

**The service has several possible implementations.** TypeScript interfaces do not exist when
the code runs, so use an **abstract class** as the token.

```ts
export abstract class Cache {
  abstract get(key: string): Promise<string | undefined>;
}

@Service()
export class RedisCache extends Cache { /* ... */ }

services: [singleton(Cache, RedisCache)];   // "when someone asks for Cache, give RedisCache"

class Uses {
  constructor(private readonly cache: Cache) {}   // no decorator needed
}
```

**The value is not a class at all**, such as a settings object. Create an `InjectionToken`
and ask for it with `@Inject`.

```ts
export const CONFIG = new InjectionToken<{ port: number }>('CONFIG');

services: [value(CONFIG, { port: 3000 })];

class Server {
  constructor(@Inject(CONFIG) private readonly config: { port: number }) {}
}
```

Add `@Optional()` to a parameter to receive `undefined`, instead of an error, when nothing is
registered for it.

## Without decorators

If you want a class but no decorators, list what it needs in a static `inject` array, in the
same order as the constructor parameters.

```ts
class UsersRepository {
  static inject = [Database, { token: CONFIG, optional: true }];

  constructor(
    private readonly db: Database,
    private readonly config?: Config,
  ) {}
}
```

## Keyed services

To register several implementations of one token and pick between them, give each one a key.

```ts
services: [
  singleton(Storage, S3Storage, { key: 's3' }),
  singleton(Storage, DiskStorage, { key: 'disk' }),
];

class Uploader {
  constructor(@Inject(Storage, 's3') private readonly storage: Storage) {}
}
```

## Several registrations of one token

You can register the same token more than once. `get()` returns the last one registered.
`getAll()` returns all of them, in order, which is useful for a list of plugins.

```ts
provider.getAll(HealthCheck).map((check) => check.run());
```

## Mistakes caught at startup

`Suku.create` checks every service before the server starts listening. A mistake stops the
app at once, with a message that says what is wrong.

| Mistake | Error |
| --- | --- |
| Something needs a service that was never registered. | `MissingServiceError` |
| Two or more services need each other, in a loop. | `CircularDependencyError` |
| A constructor parameter is an interface or a plain type, with no `@Inject`. | `UnresolvableParameterError` |

## A singleton that needs a scoped service [#captive-dependencies]

A singleton lives for the whole app, and a scoped service lives for one request. If a
singleton kept a scoped service, it would hold on to the one from the first request forever,
and every later request would share it. This is called a **captive dependency**.

Suku prevents it for you. At startup, a singleton that needs a scoped service **becomes
scoped itself**. So does anything that needs that service, all the way up. Each request then
gets its own copy of the whole chain.

```ts
services: [scoped(UnitOfWork), singleton(Reports)];   // Reports needs UnitOfWork

// Reports is now scoped: one per request, like UnitOfWork.
```

Because it is now scoped, you can no longer ask for it outside a request.

If you want a singleton to stay a singleton, do not put the scoped service in its
constructor. Ask for it in a route's `services` instead.

To make Suku stop with an error instead of changing the lifetime, turn the strict mode on.

```ts
await Suku.create({ di: { captiveDependencies: 'error' } });
```

```text
Captive dependency: OrdersRoutes (singleton) depends on UnitOfWork (scoped).
```

## The provider is injectable

The **provider** is the object you ask for services by hand: `provider.get(UsersService)`.
You rarely need it, because the constructor and a route's `services` do the asking for you.

When you do need it, for example to pick a service while the app is running, ask for
`ServiceProvider`. You receive the one for the current request.

```ts
class JobRunner {
  constructor(private readonly provider: ServiceProvider) {}

  run(job: Constructor<Job>) {
    return this.provider.get(job).execute();
  }
}
```

## Using the container directly

`@sukujs/di` also works by itself, with no HTTP involved. Here you create and dispose the
scope yourself.

```ts
import { ServiceCollection } from '@sukujs/di';

const provider = new ServiceCollection()
  .addSingleton(Database)
  .addScoped(UsersService)
  .build({ validateOnBuild: true });

const scope = provider.createScope();
scope.get(UsersService);
await scope.dispose();
```

A provider also works with `await using`, which disposes it at the end of the block.
