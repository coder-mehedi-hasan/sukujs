---
title: Grafana Cloud
description: Send a Suku app's logs, traces and metrics to Grafana Cloud, step by step.
---

This guide takes a Suku project from nothing to its logs showing in Grafana Cloud. It uses
the OpenTelemetry setup described in [observability](/docs/observability). You need a
Grafana Cloud account; the free plan is enough.

## 1. Add observability to the project

A new project:

```bash
suku new my-api --observability otel
```

Or one you already have:

```bash
suku generate observability
bun install
```

Both add [`@sukujs/observability`](/docs/observability) and put its middleware first in
`src/main.ts`. [`examples/logger-otlp`](https://github.com/sukujs/sukujs/tree/main/examples/logger-otlp) in the
repository is an app at this point: it only needs the two variables from the steps below.

The app now needs an endpoint to start, which the next steps get you.

## 2. Open the OpenTelemetry setup in Grafana

Open your Grafana Cloud stack. In the menu on the left, go to **Connections**, then **Add new
connection**. Search for `otlp` and choose **OpenTelemetry (OTLP)**.

![Grafana's Add new connection page, with "otlp" in the search box and the OpenTelemetry (OTLP) tile below it](/images/observability/grafana-add-connection.png)

## 3. Skip to the connection details

Grafana asks where your app runs. Your app sends the data itself, so there is nothing to
install: click **View connection details**. Choosing **Serverless / Other** and then **Next**
leads to the same place.

![The OpenTelemetry setup page asking where the application runs, with Kubernetes, Linux and Serverless / Other, and a View connection details button](/images/observability/grafana-setup.png)

## 4. Create a token

Under **Create an API token**, type a name such as `my-api` and create it. Grafana then shows
the token and, below it, the environment variables your app needs.

![The token step: a token named example-suku with write scopes for metrics, logs and traces, and the generated environment variables below](/images/observability/grafana-token.png)

<Callout type="warn" title="The token is a password">
  Anyone who has it can write data into your stack. Do not commit it, paste it in a chat, or leave
  it in a screenshot. It is blacked out in the picture above. If one leaks, delete it in Grafana and
  create a new one.
</Callout>

## 5. Put the values in `.env`

Grafana shows the values under its own, longer variable names. Copy two of them into a `.env`
file in the project, under Suku's names:

| Grafana shows                 | Put its value in |
| ----------------------------- | ---------------- |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | `OTLP_ENDPOINT`  |
| `OTEL_EXPORTER_OTLP_HEADERS`  | `OTLP_HEADER`    |

```bash title=".env"
OTLP_ENDPOINT="https://otlp-gateway-prod-<zone>.grafana.net/otlp"
OTLP_HEADER="Authorization=Basic <the long value Grafana gave you>"
OTEL_SERVICE_NAME="my-api"
```

Keep the quotes. `OTEL_SERVICE_NAME` is the name you search for in Grafana. You can leave out
`OTEL_EXPORTER_OTLP_PROTOCOL`: the app always sends the format Grafana asks for there.

The project's `.gitignore` already lists `.env`, so the token stays out of git.

<Callout title="Where the variables go in production">
  `suku dev` reads `.env` for you, because Bun does. A built app started with Node does not: set the
  same variables in your host, container or process manager.
</Callout>

## 6. Run the app and make a request

```bash
bun run dev
```

```bash
curl -H 'x-app-trace: 1' localhost:3000/hello/Ada
```

Every log line is sent. Only one request in ten is traced, so the `x-app-trace: 1` header is
there to make sure this one is. Both can be [changed](/docs/observability#options).

## 7. See it in Grafana

In the menu on the left, open **Drilldown**, then **Logs**. Choose your service name. Data is
sent every few seconds, so give it a moment.

![Grafana Logs Drilldown filtered to one service, listing INFO, DEBUG, ERROR and WARN lines, with one line open to show its fields, including trace_id and span_id](/images/observability/grafana-logs.png)

Each line keeps the fields you logged, such as `method` and `path`. It also carries a
`trace_id` and a `span_id`, which link the line to the request that wrote it.

| To see                                | Open                            |
| ------------------------------------- | ------------------------------- |
| Logs                                  | **Drilldown**, then **Logs**    |
| Request traces and `@Traced()` spans  | **Drilldown**, then **Traces**  |
| Memory, CPU time and event-loop delay | **Drilldown**, then **Metrics** |

Only lines at `info` and above are sent by default. Set `LOG_LEVEL=debug` to send `debug`
lines too.

## If nothing shows up

The app does not print anything when sending fails, so a wrong value looks the same as no
data.

- **`OTLP_ENDPOINT` must end in `/otlp`.** Do not add `/v1/logs`; the app adds that itself.
- **The zone must be your stack's.** Copy the endpoint from the page in step 4, not from this
  guide.
- **`OTLP_HEADER` must be complete.** It starts with `Authorization=Basic ` and ends with `==`
  or `=`. A line break in the middle breaks it.
- **The app must have been restarted** after you changed `.env`.
- **Look at the right time range.** The picker at the top right defaults to the last few
  minutes.

## Going to production

Grafana describes sending straight from the app as the simple setup, good for development and
testing. For production it recommends a collector, such as
[Grafana Alloy](https://grafana.com/docs/alloy/latest/), running next to your app: it retries,
batches and can drop sensitive fields before anything leaves your network.

Your app does not change. Point it at the collector and drop the header, because the
collector holds the token:

```bash title=".env"
OTLP_ENDPOINT="http://localhost:4318"
```

Grafana's own page for this is
[Send data using OTLP](https://grafana.com/docs/grafana-cloud/send-data/otlp/send-data-otlp/).
